# Engine Book Parity Matrix

This matrix tracks the relationship between:

- Book chapters and examples.
- Existing `examples/test_*.py` behavior that must remain represented.
- New or deeper tests required by the engine book.
- SRD/rules markdown consulted for each area.
- Documentation hygiene work for comments, Google-style docstrings, and Pydantic field descriptions.

Status values:

- `baseline-mapped`: existing examples cover some behavior, but deeper book parity is not complete.
- `missing`: no adequate test/example parity exists yet.
- `partial`: book example and test exist, but assertions or scope are not deep enough.
- `covered`: book example and executable test have 1:1 parity.
- `intentionally-not-tested`: behavior is documented as not appropriate for executable parity.

## Global Baseline

Current example-test baseline:

- `examples/test_*.py`: 139 files at the top level.
- Existing behavior in those files is the minimum regression floor.
- Several files are script-style or profiler-style and still count as baseline behavior, but not as sufficient deep coverage.
- Server tests under `examples/server_tests/` must be considered individually and never batch-run.

Run convention:

```bash
source .venv/bin/activate
python3 examples/test_<feature>.py
uv run pytest -q tests/book_examples/test_public_mdx_snippets.py
uv run pytest -q tests/engine_book/test_chapter_<nn>_<topic>.py
uv run pytest -q tests/engine_book/test_book_integrity.py
```

Do not use broad `pytest`. Use focused files. The engine-book suite disables
pytest capture through `pyproject.toml` so focused
`uv run pytest -q tests/engine_book/...` commands work in the Codex shell
without repeating `-s`.

The book-integrity test checks that required book files exist, each
`tests/engine_book/test_chapter_*.py` function has a parity-matrix row, no
engine-book tests remain in `examples/`, and each matrix row that names an
engine-book pytest file points back to a live executable function. Written
chapter rows must not silently regress to `TBD`/`missing`, and `pyproject.toml`
keeps pytest available through the `uv` dev dependency group with collection
rooted at `tests/` and capture disabled for this workspace. The integrity suite
also verifies that written chapters keep source, rules, parity, and hygiene
sections; that source/rules references resolve to local repository files or
globs; and that active runtime source roots do not reintroduce Claude
references after the Codex migration.
