# BG3 icon study and original CIE28 direction — 2026-10-06

The previous icon bank loses meaning when detailed miniature illustrations are reduced to 28 pixels. The direction tested here is a small family of readable magical glyphs, informed by BG3's ability icons and coloured with our existing game palette. Inventory objects are a separate visual family.

**Status:** scan initiated 2026-10-06; preview verified 2026-10-07. Completed reference study and six original style candidates; user visual review is pending. The previous bank's earlier approval does not establish approval for this new direction. No replacement icon bank is installed by this study.

The family sheets contain 144 original samples. An additional 34 desktop/controller/condition selections support direct size comparisons.

1. **Abilities are usually glyphs.** A limited coloured contour describes a weapon, gesture, creature or magical action. Large open interiors carry the meaning. Fire Bolt uses a pointed flame arrangement; Fireball uses a rounded flare; Scorching Ray uses several directional streaks. Lightning Bolt and Chain Lightning differ in branching arrangement. The shape communicates the difference before the label does. [Spell icon examples](https://bg3.wiki/wiki/Category:Spell_controller_icons)
2. **Related choices share structure and change the meaningful part.** Protection from Energy repeats a shield with a different element inside. Command uses different hand gestures. Eyebite retains an eye while changing the central outcome. Conjure Elemental repeats its summoning form while changing the element. This is stronger than recolouring the same picture. [Choice family evidence](/home/tommaso/.codex/worktrees/1aac/dnd_engine/output/weapon-vfx/bg3-icons-study-2026-10-06/review/family-spell-choice-families.png)
3. **Weapon actions communicate verbs.** Basic attacks show a weapon; special attacks add the particular contact, motion or displacement. Melee/ranged manoeuvre pairs retain the same idea and substitute the weapon. A generic sword with another glow would obscure these distinctions. [Weapon action evidence](/home/tommaso/.codex/worktrees/1aac/dnd_engine/output/weapon-vfx/bg3-icons-study-2026-10-06/review/family-class-and-weapon-actions.png)
4. **Colour supports the silhouette.** The inspected examples use warm orange/gold for many attacks and radiant effects, blue for lightning and cold, cyan/teal for healing, and pale tones for many ordinary actions and passives. Pink/violet appears in several control spells. These are observed tendencies, not an exact universal school-colour rule. Our candidates use the existing game palette rather than copying BG3 colours literally. [Spells](/home/tommaso/.codex/worktrees/1aac/dnd_engine/output/weapon-vfx/bg3-icons-study-2026-10-06/review/family-spell-grammar.png), [passives](/home/tommaso/.codex/worktrees/1aac/dnd_engine/output/weapon-vfx/bg3-icons-study-2026-10-06/review/family-passives.png)
5. **Conditions are a separate family.** Some use simple flat symbols, such as the crossed eye, skull, falling figure and snowflake; others reuse an ability glyph inside a circular backing. Ability buttons and overhead condition markers should not be conflated. The existing approved overhead markers remain their own delivery. [Condition evidence](/home/tommaso/.codex/worktrees/1aac/dnd_engine/output/weapon-vfx/bg3-icons-study-2026-10-06/review/family-conditions.png)
6. **Items differ from abilities.** The inspected potions, weapons and ingredients are small material paintings. They describe an object, rather than an action. An inventory study should preserve this distinction and simplify the object silhouette for our lower resolution. [Item evidence](/home/tommaso/.codex/worktrees/1aac/dnd_engine/output/weapon-vfx/bg3-icons-study-2026-10-06/review/family-items-are-a-different-family.png)
7. **BG3's frame is not the glyph.** The desktop files often include a textured backing; the larger controller variants expose the glyph more clearly. Our art should contain only the motif. Slot background, pixel border, selection and cooldown treatment belong to the UI overlay. [Desktop/controller pairs](/home/tommaso/.codex/worktrees/1aac/dnd_engine/output/weapon-vfx/bg3-icons-study-2026-10-06/review/selected-bg3-originals.png)

## Proposed style adapted to our graphics

These are design proposals drawn from the evidence:

- One dominant metaphor and at most one secondary cue. Recognition takes priority over ornament.
- Broad angular coloured strokes, normally about two final pixels thick. Important interior gaps should survive as about two final pixels, rather than closing during reduction.
- Two or three dominant tonal groups, with a restrained highlight. CIE maps the raster into our existing 64-colour palette; it does not make an unclear design readable.
- Empty outer margins and genuine transparent alpha. Quiet dark slots are supplied by the interface. No baked gold frame, vignette, coloured rectangle or oversized bloom.
- Variant families share their semantic base and change a readable symbol, count or gesture. Summon choices use an authored creature/element emblem, rather than a pasted gameplay sprite.
- Prioritize player spells, class actions and their actual selectable choices. Click-driven environment interactions do not need to inflate the action-bar inventory.
- Keep Slow-the-spell distinct from reduced movement speed, and keep ability art distinct from overhead markers. Icon styling must not invent or rename gameplay mechanics.
- Author the native deliverable at **28×28**, inspect at 1×, and enlarge only by integer nearest scaling. Touching slots keep zero spacing and a separate optional pixel overlay, as previously requested.

The candidates were generated using the built-in image tool with the actual game pixel reference, existing palette and BG3 reference board. They are new compositions. Each master is preserved under `authoring/candidates/`, with its exact prompt, references and original generated-output path.

Final processing is a premultiplied Lanczos resize directly to 28×28 followed by one existing CIE76 palette pass. There is no second pixelation pass, arbitrary enlarged runtime master or baked frame. The profile is `authoring/ui-cie-block1.json`; its inherited profile ID mentions an older 56px trial, but the manifest and actual image dimensions here are 28×28.

Healing Word was revised once: the first mouth outline became ambiguous at native size. The current candidate uses a restoration cross with two voice strokes; the first master and prompt are retained with the `-v1` suffix.

Self-review: Hold Person, Dash and Twinned Spell use clearer semantic shapes than the previous samples. Fire Bolt remains close to a familiar projectile metaphor, so future Fireball/Produce Flame designs must differ in geometry and scale. Rage's shouting face needs comparison against fear-related icons before using it across the bank. The six samples establish a direction for review; they do not prove every future icon is solved.

## Verification and delivery boundaries

- All downloaded originals passed byte-count, source-hash, decode and dimension checks.
- All six final candidate PNGs are 28×28 RGBA, with real transparency and transparent corner pixels.
- The comparison preview loads all six candidates, supports native and integer inspection scales, and leaves slot spacing at zero.
- The separate border is optional and can be toggled without modifying the art.
- Generation masters load only when their disclosure is opened.
- The reference library renders at most 96 entries per page, with lazy image loading. Search, bank filtering, category filtering and pagination were exercised.
- Browser result: `passed`. [Recorded checks](/home/tommaso/.codex/worktrees/1aac/dnd_engine/output/weapon-vfx/bg3-icons-study-2026-10-06/review/browser-check.json)

This delivery changes only private study output and this Markdown documentation. It does not edit gameplay, backend mechanics, the live HUD or the installed icon bank.

## Next bank pass once the direction is reviewed

Use the existing icon coverage and choice manifests as the semantic inventory; do not restart from an incomplete spell list. Apply one consistent action-glyph family to spells, class actions and choices, and a separately simplified object family to inventory items. Compare sibling choices in a touching native-size strip before expanding each family. Regenerate confusing motifs rather than repeatedly pixelating the same detailed image.

## Local implementation review

**Anti-slop:** one reference mirror, one CIE processing path and one bounded comparison preview. Original reference art and original candidates remain separated. Full-bank generation, HUD redesign and unrelated VFX exports are outside this study.

**ECS / anti-OOP:** no runtime or gameplay abstraction was introduced. This is an offline asset study with plain manifests and small deterministic scripts.
