# Feature/world condition and handler audit — 2026-10-16

This is source evidence for the Bevy design review, not parity qualification. No production code or tests were changed. The AST inventory is a discovery index, not evidence that its enclosing methods were all read. Coverage below deliberately distinguishes reviewed condition lifecycles and processor bodies from unread surrounding action/composition code. The companion `features-world-coverage.tsv` assigns every one of this partition's 1,178 inventory rows a status. No Bevy gameplay implementation or new executable proof was produced by this audit.

## Coverage and limits

The shared inventory assigns this partition 115 condition classes, 6 handler classes, 55 handler construction sites, 55 processor arguments, 63 registration/direct-dispatch sites, 27 contextual callable arguments, 27 contextual constructions, 84 condition construction sites, 319 condition methods, one processor reassignment and 426 interaction calls, across 66 files. These are static sites, not runtime instance counts. Transitive subclasses matter: BurningWeb, DivineEminenceActive, the six coating conditions and configured monster trait subclasses cannot be omitted because their immediate base lacks the word `Condition`.

All 115 condition declarations have been inspected for rule-bearing data and their owned lifecycle implementation was mapped, including inherited family implementations. All 55 handler construction/processor configurations were inspected; their processor bodies were traced in the family sources discussed below. All 27 contextual callable expressions and their concrete evaluator bodies were inspected. This does **not** mean all source files are behaviorally reviewed. Every indexed local condition method and indexed action/construction integration method has now been read. Unindexed helper paths and full surrounding files are not thereby covered. Fifty-three infrastructure rows are explicitly ROOT_OWNED, and 52 permanent-grant rows are SECOND_WAVE_OWNED by the foundation agent. This report does not claim to qualify those other agents' integration on their behalf. Two collection `.remove` calls are confirmed AST false positives.

Read in depth: all spatial mechanics/lifecycle families; class condition apply/remove/owned-state methods and concrete event/contextual processors; monster condition lifecycles and processors; racial processors; property/coating ownership; body responses/residues/transforms; summoning admission, commit, removal participants, pre-completion and settled hooks. Read selectively: installed class/origin grants and their shared reaction-source admission, item doorway retry, destruction debris placement callback. A second pass read all remaining indexed local action/construction method bodies: Rage/Frenzy/Reckless and sorcerer root admission; potion/coating activation; item doors/levers/torches; ground/trap hardware and liquid spill destruction; beast/fiend/circus constructors; skeleton marking, multiattack and summon dismissal. Root-owned infrastructure and second-wave-owned permanent grant receipts are explicitly delegated coverage, not silently counted as read here.

## Design assessment and required proofs

The design already names canonical retained events, shared graphs, exact action identities, suppression, queued child dependencies and causal completion. Those mechanisms can represent the observed rules. The source does not support a claim that every scoped mechanic has already been translated or proven. Sections 23–25's small native probes are substantially narrower than this evidence. A claim that reviewed architectural categories are covered must retain the following explicit gaps:

1. Qualify pre-completion **replacement** of a shared Restrained manifestation and attachment to surviving leases, including standalone replacement and veto. This is distinct from merely retaining shared children during removal.
2. Qualify runtime lifecycle exposure beyond EventHandler: membership-change callbacks, owner-placement callbacks, prepared-removal participants, graph-settled hooks and close/reset callbacks. Component removal alone does not encode admission or callback order.
3. Qualify Metamagic's installed-future-template mutations and phase-sensitive consumption. Keep template/execution snapshots and ownership edges separate.
4. Qualify a plate pulse whose first mechanism causes same-plate release, then whose second pulse still fires. Include control-driven pending door close supersession and actual departure as new cause.
5. Qualify entry portal reveal, nested exit hazard/save/retreat and actual final position while recording original crossing endpoint. Include two contenders for one exit and canonical ancestry-based retreat.
6. Qualify material replacement failure restoring original footprint, partial same-content displacement, Wet overlap shared manifestation, moving field exclusion and suppression without losing membership lifetime.
7. Qualify two concurrent proposed damage applications sharing Smite slot/Lucky points/bonus-damage marker/protector reaction/Leadership aura. Show deterministic admitted order and random request assignment; different recipient IDs do not establish independence.
8. Qualify injury → body response → residue deposit/provenance → canonical injury capture, including positive temp-HP-only damage exclusion, connected dread ground and nested retreat/pressure interactions.
9. Qualify source removal while Ghoul paralysis, item coating, Draconic Presence immunity, summoned existence or control remains. Preserve each source's actual authority/lifetime behavior rather than one universal linked despawn.
10. Qualify summon control-only loss against existence loss/defeat and graph-settled retirement, with agency revoked before roster mutation and publication failures after commitment.
11. Qualify Life Drain's cumulative max-HP arithmetic and instant death, recovery on long rest/removal, and exact health snapshots.
12. Qualify contextual evaluator inputs (sunlight, adjacent ally agency, magical/tagged save context, live strength/equipment/sight) at their consumed boundary; queued stale inputs require revalidation or explicit snapshots.

Source ambiguity needing targeted existing-behavior confirmation: IceSurface turn-end handler explicitly requests EXECUTION (`environmental_conditions.py:663`), while generic area installation only hard-codes EFFECT for positional handlers and registers turn handlers through their own triggers. Preserve this distinction; do not rewrite every area trigger as Effect merely because the table-building loop contains Effect. No source repair is proposed here.

The antiOOP check rejects recreating BaseCondition/Creature inheritance or a universal callback object store in Rust: use typed payload/config components, native rule systems and explicit domain ownership/continuation data. The antislop/adherence check rejects expanding this audit into performance polishing, source rewrites or a new universal scheduler framework. This audit supplies concrete required semantics and falsifiable proofs; it does not make the probes prove those semantics.

This agent read those rule bodies and does not substitute a guessed dispatcher policy for the root audit.
