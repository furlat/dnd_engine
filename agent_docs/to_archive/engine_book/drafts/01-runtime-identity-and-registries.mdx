Every action in a tactical videogame touches objects that must still be available later. A hero moves. A condition remembers who applied it. A value contributes to a roll. An item sits in a pack, on the floor, or in an equipment slot. The engine needs a stable way to name each live thing while rules are being resolved.

NeuroDragon uses UUIDs for that stable identity. A UUID says "this exact runtime object," and a registry says "recover it through the family that knows what kind of object it should be." This chapter teaches that lookup contract before any chapter asks you to follow values, events, conditions, actions, or actors through the runtime.

## Why Identity Exists

The engine is the software dungeon master. It receives an intent, finds the live actor or object involved, checks the rules, changes state, and exposes the result. Stable identity is what lets those steps talk about the same runtime object without passing the entire object graph everywhere.

The important idea is not "one global registry." NeuroDragon has several lookup families. Each family answers a different question:

| Family | Runtime role | Lookup |
| --- | --- | --- |
| Object | Root UUID-addressable object. | `BaseObject.get(uuid)` or subclass `get(uuid)` |
| Value | Numbers and roll states used by rules. | `BaseValue.get(uuid)` and value subclass lookups |
| Block | Containers for values and child blocks. | `BaseBlock.get(uuid)` |
| Entity | Playable or AI actor with grid position. | `Entity.get(uuid)` and position lookup |

That separation keeps code honest. If a system needs a value, it should look in the value family. If it needs an entity, it should ask the entity registry. The UUID is stable; the lookup family gives the UUID its expected meaning.

## A Small Runtime Object

`BaseObject` is the root identity model for UUID-addressable objects. A tiny subclass makes that behavior visible without introducing actors, combat, or map rules.

```python
from uuid import uuid4

from dnd.core.base_object import BaseObject


class TutorialMarker(BaseObject):
    """Small concrete object used to demonstrate registry behavior."""


source_id = uuid4()
marker = TutorialMarker(source_entity_uuid=source_id, name="door marker")

assert TutorialMarker.get(marker.uuid) is marker
```

The `marker` receives a UUID when it is created. Because `use_register` defaults to `True`, it enters the `TutorialMarker` registry during model initialization. The lookup asks the class for the object with that UUID and receives the same live instance back.

The `source_entity_uuid` field carries the identity of the entity that produced, owns, or caused an object in the subsystem using it. This chapter treats it as identity metadata. Later chapters show how actions, effects, and values use source and target identity in context.

## Opting Out Of Lookup

Some runtime objects are useful as transient declarations or temporary data. `BaseObject` supports that by letting an object skip registry participation at creation time.

```python
draft_marker = TutorialMarker(
    source_entity_uuid=source_id,
    name="draft marker",
    use_register=False,
)

assert TutorialMarker.get(draft_marker.uuid) is None

draft_marker.add_to_register()
assert TutorialMarker.get(draft_marker.uuid) is draft_marker

draft_marker.remove_from_register()
assert TutorialMarker.get(draft_marker.uuid) is None
```

An opted-out object still has a UUID. It simply does not answer lookup until it is explicitly added. Removing it from the registry disables lookup again.

## Registry Families Are Separate

Values and blocks participate in runtime identity, but they do not all live in the same lookup table.

```python
from dnd.core.base_block import BaseBlock
from dnd.core.values import BaseValue


value = BaseValue(source_entity_uuid=source_id, name="tutorial value")
block = BaseBlock(source_entity_uuid=source_id, name="tutorial block")

assert BaseValue.get(value.uuid) is value
assert BaseObject.get(value.uuid) is None

assert BaseBlock.get(block.uuid) is block
assert BaseValue.get(block.uuid) is None
```

`BaseValue` inherits the identity fields from `BaseObject`, but it defines its own registry family. A value is found by `BaseValue.get(...)`, not by `BaseObject.get(...)`.

`BaseBlock` is a different family again. Blocks are containers for values and child blocks. This chapter only needs the lookup fact; the next chapter explains what an entity-owned block actually contains.

## Entity Identity And Position

An entity is the first full actor in the manual. It is also a block, so it participates in block lookup, entity lookup, position lookup, and map position tracking.

```python
from dnd.core.base_block import BaseBlock
from dnd.core.gridmap import get_map
from dnd.entity import Entity, EntityConfig


hero_id = uuid4()
hero = Entity.create(
    source_entity_uuid=hero_id,
    name="Hero",
    config=EntityConfig(position=(2, 3)),
)

assert Entity.get(hero_id) is hero
assert BaseBlock.get(hero_id) is hero
assert hero in Entity.get_all_entities_at_position((2, 3))
assert get_map().get_entity_position(hero_id) == (2, 3)
```

`Entity.create(...)` is the construction path to use for tutorial actors. It gives the entity a matching `uuid` and `source_entity_uuid`, builds the configured child blocks, and registers the actor in the entity and block lookup surfaces.

The entity also enters position tracking. The class-level position index can recover entities at a grid cell, and the map tracks the entity UUID at the same position.

Moving the actor updates all of those surfaces:

```python
Entity.update_entity_position(hero, (4, 5))

assert hero.position == (4, 5)
assert hero.senses.position == (4, 5)
assert hero not in Entity.get_all_entities_at_position((2, 3))
assert hero in Entity.get_all_entities_at_position((4, 5))
assert get_map().get_entity_position(hero_id) == (4, 5)
```

The `senses.position` assertion is an observed ownership detail: the entity's spatial block follows the entity's stored position. The senses chapter will explain what that block computes.

## Lookup Sharp Edges

Registry lookup is intentionally typed, but each family has its own current contract.

| Surface | Practical contract |
| --- | --- |
| `BaseObject.get(uuid)` | Returns `None` for a missing UUID and raises when the UUID belongs to the wrong object subclass. |
| `BaseValue.get(uuid)` | Returns any registered value. |
| `StaticValue.get(uuid)` | Raises when the UUID is missing or belongs to another value type. |
| `ContextualValue.get(uuid)` | Returns `None` when missing and raises on the wrong value type. |
| `ModifiableValue.get(uuid)` | Returns `None` when missing and raises on the wrong value type. |
| `Entity.get_all_entities_at_position(position)` | Returns the live list stored at that position index. |

Use `Entity.create(...)` for gameplay actors. Manual `Entity.register_entity(...)` only writes the entity registry; it does not populate every lookup surface shown in this chapter.
