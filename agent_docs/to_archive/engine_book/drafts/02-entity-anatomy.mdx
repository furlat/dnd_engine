An entity is the engine's actor shell. A player character, monster, summoned ally, or arena participant becomes an `Entity` when the runtime needs to place it on the map, inspect its character-sheet state, and later ask what it can do.

The previous chapter explained how the runtime names live objects and recovers them by UUID. This chapter opens the actor named by that UUID. It does not resolve combat yet. It shows where the actor's state lives before later chapters teach how rules read and change that state.

## What An Entity Is

In D&D language, a creature has ability scores, skills, saving throws, hit points, equipment, senses, and resources it can spend during a turn. In NeuroDragon, that creature-facing idea is stored as one `Entity` with a set of actor-owned blocks.

The entity itself carries identity and actor metadata: UUID, name, position, faction, weight, creature type, size, turn state, and active conditions. Its child blocks carry the larger regions of state:

| Block | Game meaning | Runtime role |
| --- | --- | --- |
| `ability_scores` | Strength, Dexterity, Constitution, Intelligence, Wisdom, Charisma. | Owns six `Ability` blocks and their raw/modifier values. |
| `skill_set` | The 18 D&D skills. | Owns `Skill` blocks with proficiency and expertise flags. |
| `saving_throws` | Six ability-based saves. | Owns save blocks with proficiency and extra save bonus. |
| `health` | HP, hit dice, temporary HP, damage state. | Calculates current HP with Constitution contribution supplied by `Entity`. |
| `equipment` | Worn armor, weapon sets, combat bonuses. | Stores slots and equipment-derived modifiable values. |
| `inventory` | Held items. | Stores item stacks and item-provided use actions. |
| `action_economy` | Actions, bonus actions, reactions, movement, resources, spell slots. | Tracks consumable turn resources and named resources. |
| `senses` | What the actor can perceive. | Caches visible entities, objects, cells, paths, and special senses. |
| `spellcasting` | Spellcasting ability and spell-specific bonuses. | Stores spell attack, damage, DC, crit, and extra-damage modifiers. |
| `appearance` | Renderer-facing body and tint metadata. | Gives the client stable visual taxonomy. |

Those blocks are not decorative. They are the actor's organized memory. Later systems read them when they need a Strength modifier, an available reaction, current hit points, visible targets, a spell save DC, or a weapon slot.

## Where The Imports Come From

The examples in this chapter build one configured tutorial hero. Every symbol appears here before the code uses it.

| Symbol | Import | Why it appears |
| --- | --- | --- |
| `uuid4` | `from uuid import uuid4` | Creates the actor UUID for the tutorial hero. |
| `AbilityConfig`, `AbilityScoresConfig` | `from dnd.blocks.abilities import AbilityConfig, AbilityScoresConfig` | Configures raw ability scores. |
| `SkillConfig`, `SkillSetConfig` | `from dnd.blocks.skills import SkillConfig, SkillSetConfig` | Configures skill proficiency and expertise. |
| `SavingThrowConfig`, `SavingThrowSetConfig` | `from dnd.blocks.saving_throws import SavingThrowConfig, SavingThrowSetConfig` | Configures save proficiency. |
| `HealthConfig`, `HitDiceConfig` | `from dnd.blocks.health import HealthConfig, HitDiceConfig` | Configures hit dice and HP foundation. |
| `ActionEconomyConfig`, `RechargeType` | `from dnd.blocks.action_economy import ActionEconomyConfig, RechargeType` | Configures turn resources and named resource recharge. |
| `SpellcastingConfig` | `from dnd.blocks.spellcasting import SpellcastingConfig` | Configures spellcasting ability and spell-specific bonuses. |
| `AppearanceConfig` | `from dnd.blocks.appearance import AppearanceConfig` | Configures renderer-facing actor appearance. |
| `ModifiableValue` | `from dnd.core.values import ModifiableValue` | Lets inspection code prove discovered deep values are modifiable values. |
| `Entity`, `EntityConfig` | `from dnd.entity import Entity, EntityConfig` | Creates the actor. |

## Create A Tutorial Hero

`Entity.create(...)` is the construction path used in tutorial code. The entity receives the UUID you pass as both its `uuid` and its `source_entity_uuid`, and the configured child blocks inherit that source identity.

This hero is intentionally small but complete enough to look like a videogame actor: she has ability scores, trained skills, save proficiencies, hit dice, turn resources, a couple of spell slots, spellcasting metadata, appearance metadata, a faction, a position, and a weight.

```python
from uuid import uuid4

from dnd.blocks.abilities import AbilityConfig, AbilityScoresConfig
from dnd.blocks.action_economy import ActionEconomyConfig, RechargeType
from dnd.blocks.appearance import AppearanceConfig
from dnd.blocks.health import HealthConfig, HitDiceConfig
from dnd.blocks.saving_throws import SavingThrowConfig, SavingThrowSetConfig
from dnd.blocks.skills import SkillConfig, SkillSetConfig
from dnd.blocks.spellcasting import SpellcastingConfig
from dnd.core.values import ModifiableValue
from dnd.entity import Entity, EntityConfig


def create_tutorial_hero() -> Entity:
    hero_id = uuid4()

    return Entity.create(
        source_entity_uuid=hero_id,
        name="Aria",
        config=EntityConfig(
            ability_scores=AbilityScoresConfig(
                strength=AbilityConfig(ability_score=16),
                dexterity=AbilityConfig(ability_score=14),
                constitution=AbilityConfig(ability_score=14),
                intelligence=AbilityConfig(ability_score=10),
                wisdom=AbilityConfig(ability_score=12),
                charisma=AbilityConfig(ability_score=8),
            ),
            skill_set=SkillSetConfig(
                athletics=SkillConfig(proficiency=True),
                stealth=SkillConfig(proficiency=True, expertise=True),
                perception=SkillConfig(proficiency=True),
            ),
            saving_throws=SavingThrowSetConfig(
                dexterity_saving_throw=SavingThrowConfig(proficiency=True),
                constitution_saving_throw=SavingThrowConfig(proficiency=True),
            ),
            health=HealthConfig(
                hit_dices=[
                    HitDiceConfig(
                        hit_dice_value=10,
                        hit_dice_count=2,
                        mode="maximums",
                    )
                ],
            ),
            action_economy=ActionEconomyConfig(
                actions=1,
                bonus_actions=1,
                reactions=1,
                movement=30,
                spell_slots={1: 2},
            ),
            spellcasting=SpellcastingConfig(
                spellcasting_ability="wisdom",
                spell_attack_modifiers=[("Focus", 1)],
                spell_dc_modifiers=[("Moon Circlet", 2)],
            ),
            appearance=AppearanceConfig(
                body_category="NakedBody2",
                skin_tint=0x8A5A44,
                head_category="Head9",
                hair_tint=0x221811,
            ),
            proficiency_bonus=2,
            position=(1, 2),
            faction="heroes",
            weight=180,
        ),
    )


hero = create_tutorial_hero()

assert hero.name == "Aria"
assert hero.uuid == hero.source_entity_uuid
assert hero.position == (1, 2)
assert hero.faction == "heroes"
assert hero.weight == 180
```

The actor metadata is on the entity. The larger gameplay regions are child blocks:

```python
direct_block_names = {block.name for block in hero.get_blocks()}

assert {
    "ability_scores",
    "skill_set",
    "SavingThrowSet",
    "Health",
    "Equipped",
    "ActionEconomy",
    "Senses",
    "Inventory",
    "Appearance",
    "Spellcasting",
}.issubset(direct_block_names)

for block in hero.get_blocks():
    assert block.source_entity_uuid == hero.uuid
```

That loop is an anatomy check. The entity is the actor shell, and each direct block belongs to the same actor source.

## Character Sheet Blocks

The first three blocks look like a D&D character sheet: ability scores, skills, and saving throws.

```python
strength = hero.ability_scores.get_ability("strength")
dexterity = hero.ability_scores.get_ability("dexterity")
athletics = hero.skill_set.get_skill("athletics")
stealth = hero.skill_set.get_skill("stealth")
dexterity_save = hero.saving_throws.get_saving_throw("dexterity")
```

An ability stores a raw score and exposes a modifier. One detail matters: the raw score is available as `score`, while this ability score value's `normalized_score` uses the D&D ability-score normalizer.

```python
assert strength.ability_score.score == 16
assert strength.ability_score.normalized_score == 3
assert strength.modifier == 3

assert dexterity.ability_score.score == 14
assert dexterity.ability_score.normalized_score == 2
assert dexterity.modifier == 2
```

Skills know which ability they belong to and whether the actor is proficient or expert.

```python
assert athletics.ability == "strength"
assert athletics.proficiency is True
assert athletics.expertise is False

assert stealth.ability == "dexterity"
assert stealth.proficiency is True
assert stealth.expertise is True
```

In the config path, expertise is explicit data. If a tutorial actor should be both proficient and expert, set both flags in the config. The runtime mutator `set_expertise()` also marks a skill proficient, but data configuration should say exactly what it means.

Saving throws follow the same ability vocabulary:

```python
assert dexterity_save.ability == "dexterity"
assert dexterity_save.proficiency is True
```

## Health And Actor HP

The health block owns hit dice, temporary hit points, damage taken, damage reduction, and damage-type responses. The entity owns the actor-level HP calculation because HP depends on both the health block and the actor's Constitution.

For Aria, two maximum d10 hit dice give 20 hit-dice HP. Constitution 14 gives a +2 modifier, applied once per hit die, so current HP starts at 24.

```python
assert hero.health.total_hit_dices_number == 2
assert hero.get_hp() == 24
```

This chapter stops at the actor anatomy level. Damage application, healing events, resistances, and death handling get their own later explanations.

## Turn And Spell Resources

The action economy block stores the turn buckets a tactical videogame client cares about: action, bonus action, reaction, movement, named resources, and spell slots.

```python
assert hero.action_economy.actions.normalized_score == 1
assert hero.action_economy.bonus_actions.normalized_score == 1
assert hero.action_economy.reactions.normalized_score == 1
assert hero.action_economy.movement.normalized_score == 30
assert hero.action_economy.spell_slot_1.normalized_score == 2
```

Named resources live in the same block. A feature can add a resource with a recharge rule, consume it, and restore it at the appropriate rest or turn boundary.

```python
hero.action_economy.add_resource(
    name="Second Wind",
    maximum=1,
    recharge_type=RechargeType.SHORT_REST,
)

assert hero.action_economy.consume_resource("Second Wind") is True
assert hero.action_economy.get_resource_current("Second Wind") == 0

hero.action_economy.on_short_rest()
assert hero.action_economy.get_resource_current("Second Wind") == 1
```

Spellcasting metadata is separate from spell slots. Slots are spendable resources on `action_economy`; spellcasting stores the actor's spellcasting ability and spell-specific bonuses.

```python
assert hero.spellcasting.spellcasting_ability == "wisdom"
assert hero.spellcasting.spell_attack_bonus.normalized_score == 1
assert hero.spellcasting.spell_dc_bonus.normalized_score == 2
```

## Presentation State

Not every actor block is a combat rule. `appearance` is gameplay-inert metadata for the renderer. It gives the client stable body, head, and tint data without asking the client to infer appearance from a class name or display name.

```python
assert hero.appearance.body_category == "NakedBody2"
assert hero.appearance.skin_tint == 0x8A5A44
assert hero.appearance.head_category == "Head9"
```

That separation is useful. Designers can reason about the actor's visual identity without mixing presentation state into abilities, HP, inventory, or spellcasting.

## Discovering The Block Tree

Because `Entity` inherits from `BaseBlock`, it can expose direct child blocks and deep values through the block discovery API.

```python
strength_block = hero.ability_scores.get_block_from_name("strength")
assert strength_block is hero.ability_scores.strength

strength_score = hero.ability_scores.strength.get_value_from_name(
    "strength Ability Score"
)
assert strength_score is hero.ability_scores.strength.ability_score
```

Deep value discovery walks through the actor's child blocks and finds the modifiable values inside them.

```python
deep_values = hero.get_values(deep=True)
deep_value_names = {value.name for value in deep_values}

assert all(isinstance(value, ModifiableValue) for value in deep_values)
assert "strength Ability Score" in deep_value_names
assert "Actions" in deep_value_names
assert "Spell Attack Bonus" in deep_value_names
```

This is inspection, not rule resolution. It is how you can see that actor state is organized and navigable before learning how modifiers, dice, events, actions, and conditions use those values.
